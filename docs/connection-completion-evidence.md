# Connection completion evidence (0.8.0)

Connection planning now reviews the configured materials, not an operation's purpose as a substitute for its actual arguments. This contract is incompatible with the previous boolean assessment wire and existing connection checkpoints. Start a new connection session; do not invent scopes, convert old boolean judgments, or reuse old evidence IDs.

## Ownership and evidence

API argument generation retains its existing original-literal verification. Connection intake rechecks supplied source receipts against current values and original message locations before invoking a model. Enum interpretation receipts are separately replayed against their original source context and compared with the current operation and configured value; an interpreted enum is not relabeled as a copied literal. Attributed materials require authoritative `literalSourceMessages`; goal or repair prose cannot replace them. Connection review does not generate replacement values. The private catalog explicitly projects the original verified receipts instead of reading the planning projection that intentionally omits audit metadata. It also contains requirements, operation identities, actual arguments, request/response contracts, native settings, the complete material inventory and working graph.

Evidence IDs are code-derived content fingerprints. The adapter's assessment object has exactly one code-owned key per semantic goal. Each goal selects one offered pointer or explicit null per evidence ID in a strict map. Original fact references and workflow graph evidence are mandatory for their goal scopes. Duplicate goals/references and invented pointer roots are not representable. Code supplies scope, derives causal node IDs and copies original text; models do not regenerate these fields. Core receipts use explicit assessment arrays and `evidenceRefs`, including `/text` and an unchanged quote for requirement references. A conclusion needs every goal fact and current material evidence, plus graph evidence for workflow scope. Code verifies references and freshness; it does not prove semantic truth or complete coverage of every natural-language clause. Initial independent goal coverage review remains separate. Never forward this private catalog to browser events or copy credentials into it.

## Scoped judgments

Semantic goals declare `scope: materials` for operation selection, actual arguments, and native settings, or `scope: workflow` for meaning that depends on the resulting connections. An assessment contains `goalId`, `scope`, `status`, `nodeIds`, `evidenceRefs`, and a short reason. Status is `satisfied`, `violated`, or `insufficient-evidence`.

Unreviewed goals appear in `unassessedGoalIds`; they are not failed semantic checks. `unmetGoalIds` contains structural failures and explicit violated judgments. `insufficientEvidenceGoalIds` identifies a settled judgment that more evidence is needed. None of these states is completion. A review of one scope preserves valid assessments of other goals. Graph patches preserve material-only judgments and invalidate workflow judgments. Material revisions invalidate references whose facts or causal inputs changed, including referenced contract changes. Historical receipts are replayed against the graph that existed at that receipt. Native material extension uses the existing source-revision boundary: preserve the original `previousSession`, create a new source epoch, retain executable wiring and only valid assessments, and invalidate changed inventory evidence. Old receipts are never replayed as though they described the expanded inventory.

## Host control flow

After structural obligations finish, code switches to an independent fixed-material audit prompt and a review-only schema. Prior verdicts, unmet flags and rejected explanations are not semantic authority in that call. The review checks each configured instance against its own original clauses and distinguishes an excluded operation in a plan from unrequested guarantees about a remote implementation's internal effects.

After applying and publishing a step, inspect completion and call `assertWorkflowConnectionReviewCanContinue(inspection)` before reserving another model call. The reference LangGraph does this. The guard throws `WorkflowConnectionCompletionIncompleteError` for explicit semantic violations or insufficient evidence. It does not throw for goals that have not yet been reviewed. A rejected semantic completion submission with submitted assessments raises `WorkflowConnectionCompletionEvidenceError` immediately; it must not enter the ordinary connection-proposal retry ledger. Empty structural completion checks retain the existing material-revision route.

The independent review receives the actual offered native capability index as well as its matching schema choices. A missing supported instance can request its existing owning augmentation stage; that request is not an approval. When repair is supported, the model can use the existing `replan-materials` action to request the responsible argument, binding, native dependency, or native parameter stage against the unchanged original requirements. It does not supply replacement values in the connection decision. If a review instead reports missing evidence or an unresolved violation, the host must stop explicitly or obtain new material/evidence through an authorized path. It must not resubmit the same state until a rejection budget expires, approve an unsupported claim, or ask users to repair technical wiring.

Keep the original proposal and typed failure private. A product may project safe failure counts and a clear message; it must not serialize raw material, source quotes, model proposals, or credential values into public events. Planning completion is distinct from successful execution of external APIs.

## Verification

Focused regressions cover current values, source quotations, unknown/duplicate/stale references, missing fields, scope mismatch, graph-dependent invalidation, material evidence retention, JSON replay, and explicit incomplete termination. The real reference LangGraph test makes one insufficient-evidence assessment and stops before another model reservation. Release records must distinguish these deterministic tests from live model, browser, and engine execution.

The assertion capability now declares its actual success object (`pass: true` and the configured `assertionCount`) as a native output contract. Failures still throw; execution behavior is unchanged. Merge append describes its actual item-preserving stream semantics rather than implying a single combined object. These contracts describe supported configured behavior, not actual business API success.

`compose-native-outputs` combines named fields from configured native producers into one typed JSON object. Its all-input join and field references use the actual selected producer order. Complete source contracts are validated; missing pointers, stale source contracts, duplicate labels and ambiguous multiple source items fail. It does not infer a schema or fabricate a comparison result.
