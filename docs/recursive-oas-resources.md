# 재귀 OAS 계약의 JSON 경계

2026-11-03의 0.7.2 릴리스 준비 기록이다. 공개 패키지와 제품 설치 버전은 아직 0.7.1이며, 사용자는 0.7.2 게시·로컬 적용·재시험을 승인했다.

## 원인과 수정

OAS의 정적 `$ref`는 자기참조·상호참조를 표현할 수 있다. 기존 Core는 Scalar가 참조를 해제한 객체 그래프를 그대로 operation 계약으로 복제했다. 이 그래프가 순환하면 clarification의 문맥 식별값, 체크포인트, 모델 문맥, 응답 검증기 생성에 필요한 JSON 직렬화가 실패한다.

원본 문서는 기존 catalog의 source snapshot으로 그대로 보존한다. Scalar가 검증한 실행 중 그래프는 API 계약으로 전달하기 전에 스키마 자원으로 묶는다. 재귀 간선을 명시적인 `$ref`로 표현하고 도달에 필요한 정의를 `$defs`에 보존한다. 자원 ID는 묶인 내용의 해시로 계산한다. 실제 데이터의 null·기본값·필드·검증 규칙을 바꾸지 않는다. 순환 객체를 생략하는 JSON replacer나 깊이 제한으로 스키마를 자르는 처리는 추가하지 않았다.

API 본문·파라미터·응답에서 값을 추출할 때는 원래 참조 범위를 유지하고 필요한 정의를 함께 반환한다. 필드 포인터는 입력 포인터가 진행하는 만큼 참조를 따라가며, 같은 위치에서 진행하지 못하는 참조 순환은 명시적으로 거절한다. 배열 항목과 객체 항목 추출도 같은 참조 문맥을 사용한다. 재귀 요청의 필수값 검사는 실제 데이터 경로를 따라 누락 위치를 반환한다.

서버의 투영·검증기 생성은 기존 schema resource compiler를 사용한다. n8n 실행 중 컨테이너 종류를 판별하는 코드는 정적 참조 위치를 찾는 순수 resolver만 사용한다. Node 암호화 모듈·Ajv 컴파일러·네트워크 조회는 실행 번들에 추가하지 않았다. 합성 모델을 사용하는 LangChain 회귀로 참조가 보존된 계약의 문맥 식별값과 사용자 출처 검증을 확인한다.

## 검증 범위

- OAS 3.0·3.1·3.2의 자기참조, 상호참조와 공유 선언
- 원본 명세 보존, operation·clarification round의 JSON 왕복
- 중첩 응답과 요청의 정상값·잘못된 타입·nullable 원소
- 깊은 응답 필드, 배열 항목, 객체 항목의 투영과 검증
- 중첩 필수값 누락 위치, 바인딩된 요청 필드, composition 기반 컨테이너 판별
- 해석할 수 없는 참조의 명시적 실패

`npm run test:recursive-oas-local-n8n`은 합성 로컬 HTTP 서버와 실제 n8n 2.37.10을 사용한다. OSS 템플릿 컴파일러가 생성한 요청·응답 검사·비교 Code로 정상 및 nullable 응답을 통과시키고, 잘못된 중첩 타입과 비교 불일치를 거절한다. 실행 데이터는 메모리 파일 시스템에 두고 컨테이너와 함께 제거한다.

회사 명세는 이 공개 저장소에 복사하지 않았다. 외부의 비공개 시험 폴더에서 실제 세 Dev 명세의 96개 operation을 JSON으로 직렬화하고 clarification 문맥을 구성했다. 원래 여섯 조회 입력과 수집·가격 비교를 명시한 draft는 26개 n8n 노드, 입력 슬롯 0개, 시작 연결 활성 상태로 컴파일됐다. 실제 Dev 응답의 전체 계약 검사와 가격 비교가 통과했으며, 각 상품의 가격을 실행 중 메모리에서만 바꾸는 세 조건에서는 비교 노드가 실패했다. 업무 API에 값을 쓰지 않았다. 모델이 원문부터 새로 계획한 결과나 제품 브라우저 전체 생성의 검증을 뜻하지 않는다.

## 남은 제한

이 수정의 묶음 생성은 해석된 **정적 참조**를 대상으로 한다. 재귀 정적 자원을 재배치하면서 `$dynamicRef`·`$dynamicAnchor`·`$recursiveRef`·`$recursiveAnchor`의 범위가 함께 바뀌는 경우는 의미를 추측하지 않고 오류로 중단한다. 스키마 밖에서 발생하는 구조적 순환도 출처 경로를 표시해 거절한다. 모든 OAS 기능이나 동적 참조 지원을 검증한 결과로 보지 않는다.

기존 Ajv의 `__proto__` 관련 runtime slot 회귀 실패는 이 변경과 별도로 남는다. 제품은 공개 버전만 설치하는 정책을 유지한다. 새 버전의 소스 동기화·태그·npm·GitHub Release와 제품 적용, 실제 모델을 사용하는 브라우저 전체 재시험은 승인된 후속 작업이며 이 기록 시점에는 완료 전이다. Cloud 배포는 포함하지 않는다.

추가로 같은 재귀 타입을 두 API 결과의 `prefixItems` 위치에 함께 담는 합성 워크플로도 검증했다. Core는 예시 데이터와 구분해 선언된 스키마 자원의 URI를 색인하고, 서버 투영과 n8n 검증기 생성에서 안쪽 자원을 먼저 등록한다. 같은 URI의 동일한 자원은 한 번 등록하고 서로 다른 선언은 충돌 오류로 중단한다. 상대 ID의 기준 URI도 유지한다. 두 조회의 수집 결과를 후속 native 입력으로 검증하는 실제 n8n의 네 조건이 모두 기대한 성공·실패로 끝났다.

최종 검사에서 타입·빌드·lint·포맷과 그래프 문서 일치 검사가 통과했다. 전체 `npm test`는 1,929개 중 1,928개 통과이며 기존 Ajv 특수 키 회귀 1건이 실패했다. 관련 집중 검사는 36개가 통과했다. 실행용 포인터 해석기는 OAS intake가 만든 닫힌 참조 자원만 읽으며, 해석되지 않은 상대 참조는 출처 오류로 중단한다. 브라우저 전역 객체와 프로토타입 조작 함수가 제한된 VM에서도 재귀 바인딩의 배열 생성과 요청 검증을 확인했다. 신규 의존성이나 dependency override는 최종 소스에 남기지 않았다.
