## Changes and compatibility

See [the public notes](0.10.0-notes.md). Tracked literals now have two explicit semantic stages: concrete destinations, then destination-scoped original source choices. Core projects only the selected finite paths and retains referenced recursive schema resources. JSON candidates are checked against each destination's value schema before exposure, and text sources are checked against that same contract. Full OAS assignment, original source validation, confirmed/bound ownership and cancellation remain enforced. Original-source mutation after the destination call fails before the source call.

The new model protocol changes call reservations even though the public argument function's input/result shape remains stable. The reference connection host reserves up to two calls for a dependent tracked-literal task. Optional enum interpretation may add another call in consumers that enable it. Untracked legacy generation is unchanged. Existing custom models, budgets and persisted outputs need an explicit compatibility review; no automatic state migration is claimed.

## Verification before version alignment

Root type checking, lint and formatting passed. The root unit suite completed 1,985 tests: 1,984 passed, one failed, none skipped or cancelled. The failure is the existing Ajv `__proto__` runtime-assignment regression recorded in 0.9.0. It remains an accepted limitation, not a passing test or a clean audit. Regression coverage includes string and numeric arrays in one request, recursive and dynamic target paths, wrong source identities, source mutation, enum decisions, cancellation, bounded recovery, checkpoints and actual LangChain HTTP tool schemas. Graph reproducibility and documentation links passed 6/6.

A captured real failing input and its unchanged recorded numeric proposal were replayed against the new source. The former numeric selection was rejected by the model-facing schema; an original-text control passed as string array values. A separate new real-model invocation on the exact captured argument task also passed with string values and no unresolved inputs. These are different checks and are not added together as full workflow runs.

The private six-role input probe reused the exact captured first task; other roles were explicitly assigned as test inputs from the original messages and originally selected operation identities. Five roles became ready and one returned a genuinely missing required classification. The user supplied that value. Its first new model proposal selected the whole answer and was rejected; one explicit replan with unchanged source and retained validation feedback selected a valid original span. No generated value was manually repaired. The original rejection remains in the private evidence. Feedback fields for that follow-up were recovered from the complete structured error dump; it is not described as a separately captured raw provider response.

All six ready request values were compiled into an explicitly independent test workflow and executed on real n8n 2.37.10. All 13 nodes completed, all six Dev requests returned HTTP 200, and all six decoded responses matched their OAS schemas. A private test specification explicitly declared anonymous access for one operation after an actual anonymous HTTP 200; this does not change or prove an upstream security contract. Containers used tmpfs, execution saving was disabled, and containers were removed. Raw business response bodies were not persisted or published. These checks do not cover newly generated comparison/collection wiring, full browser regeneration, remote registration or company deployment.

The first standalone token request failed because that diagnostic process omitted the existing host's system-CA setting. Repeating the probe with the explicit matching system-CA setting succeeded with TLS verification enabled. The environment mistake is not treated as a product transport defect.
