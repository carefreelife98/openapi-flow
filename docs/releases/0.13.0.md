## Scope

The change replaces model-owned lexical attribution in new opt-in value and reply APIs with actual OAS values and code-owned attribution. It also adds joint producer selection, separates identity capture from contract preparation, avoids unused lexical inventories in JSON consumers and reuses private standalone validators by content and dialect while preserving exported schema resource identities. Existing source-based public APIs remain compatible.

Public packages contain generic library code and synthetic fixtures only. Private host source, original requests, OAS snapshots and probe artifacts remain outside the public source/package set.

## Known limitations

The installed Ajv runtime filters `__proto__` from schema-property enumeration, so a valid declared key is rejected as an additional property. No key renaming, compiler monkeypatch or schema relaxation is included. Existing dependency advisories are not resolved or re-audited by this change.

The new value tool and follow-up reply tool intentionally use non-strict function calling for partial OAS objects. Syntax/type mistakes can still be proposed; the unchanged local OAS compiler owns per-call rejection. Source membership and valid schema choices do not prove the model selected the user's intended meaning. A syntax-level whole-proposal error or interrupted invocation has no accepted receipt. Hosts retain only earlier independently checked batches and own explicit bounded retry/review policy.

The existing example graph continues to demonstrate its compatible protocol. Its current-work annotation is refreshed from the actual compiled graph; new product-only nodes are not added to that example topology.
