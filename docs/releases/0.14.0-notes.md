# v0.14.0

This release adds an opt-in structured execution program API. Existing workflow connection planners remain available; consumers select the new protocol explicitly.

The model selects sequence, parallel and exclusive branch structure over already prepared nodes. Core lowers that structure to validated connections, checks every prepared node is represented once, preserves protected connections and validates source-bound receipts. The n8n adapter supplies explicit parallel barriers and exclusive rejoins; LangChain supplies strict structured planning and independent semantic review with scoped material repair requests.

Prepared source snapshots own immutable JSON and reuse validation only for the unchanged revision. OpenAPI 3.0 normalization no longer repeatedly clones complete descendant subtrees. Modified sources require fresh preparation and validation. Contradictory exact-value goals against the same material field are rejected rather than accepted as separate requirements.

Packages: [Core](https://www.npmjs.com/package/@openapi-flow/core/v/0.14.0), [LangChain](https://www.npmjs.com/package/@openapi-flow/langchain/v/0.14.0), [n8n](https://www.npmjs.com/package/@openapi-flow/n8n/v/0.14.0).

## Compatibility and limits

The new API is additive. A host must supply explicit source arrays, limits and a bounded orchestration policy. Runtime capability implementations and control factories must stay outside checkpoint data. New program-mode hosts do not use legacy connection field-goal or edge proposal stages.

Execution programs describe a finite workflow-level directed acyclic graph. A parallel barrier requires exactly one completion item from each branch; general item streams, zero-item branch completion, loops and arbitrary batch semantics are outside this contract. Unsupported requirements must be reported explicitly. Terminal independent branches preserve separate outputs instead of inventing a final join.

Structural validation does not prove business intent, future response values or hidden remote implementation behavior. Semantic review is distinct and may ask a business question or request bounded repair of prepared settings. Safe partial delivery retains only dependency-closed, reviewed portions; it does not certify unreviewed work as complete.

## Verification and unresolved limitations

The source suite passed 2081 of 2082 tests. The existing Ajv runtime failure for prototype-looking JSON keys remains; this is not an all-green release. Type checking, lint and formatting are checked separately in the detailed verification record. Synthetic execution on local n8n 2.37.10 covered five workflows and 25 HTTP requests: an existing join, a generated barrier, each exclusive branch before a barrier, and terminal independent outputs. No company OAS, business payload, credential or private artifact is included.

A fresh all-dependency consumer installation exceeded its 300-second timeout before verification; no passing clean installation is claimed. Isolated source archive checks do not substitute for the public-registry host installation.

Package publication is separate from host installation and service deployment. This candidate does not claim either deployment or a complete browser demonstration.
