## Reproduction and changes

A shared API alternative question described several requested calls, but its single-choice answer resolved to one `SelectedApiOperation`. Downstream preparation correctly created one call per selected entry; the lost cardinality originated in the question contract. The new explicit call-choice contract preserves each declared purpose without parsing counts from natural language or inventing extra calls. Model-wire schema, source-bound question identity, Core answer expansion and the example answer boundary are updated together.

Native role material exposed accepted parameter-reference protocols but omitted output-reference protocols. A model could consequently select a control-only role as if it produced a JSON value, then request an unavailable output contract at parameter generation. Core's existing producer eligibility correctly excluded that role. The fix derives potential output protocols from the same registered implementation properties and supplies them at selection, dependency and value stages. Actual configured output schemas remain mandatory; no future schema, fallback value or feature-name blacklist is added.
