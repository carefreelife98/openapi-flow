# 0.2.0 release-candidate criteria

Status: preparation only; no publication or release approval. Evaluation design frozen on 2026-10-16 before the new model evaluation. The owner explicitly chose to decide numeric quality thresholds after reviewing the results. The earlier 90% proposal is not an active gate.

## Product boundary

Composable libraries for host-reviewed Manual Trigger / outgoing REST workflows. Core accepts standards-valid OAS independently of adapter support. The host supplies its model, approved native capabilities, deployment configuration and credential references. The host owns review, LangGraph control flow, clarification/reselection/retry policy, import and execution. This is not an autonomous test service or a guarantee of natural-language correctness.

Existing JSON/form request mappings, response preservation, literal and response/native-output bindings, supported conditions/joins and explicit item execution remain in scope. Additional authentication/body formats and further webhook/callback implementation remain deferred. Existing limitations must be documented, not silently repaired or removed from evaluation.

## Deterministic gates

All required checks must pass: build/typecheck, lint/format, unit tests, real-OAS intake, pinned isolated n8n regressions, strict independent tarball consumer, package version/export/file/dependency checks and current dependency audit. No missing required inputs, unapproved external destination, credential leak, type coercion, plan repair or unsafe automatic execution is acceptable. Invalid data and unsupported plans must fail or remain explicitly reviewable.

The independent consumer must use installed tarballs, `strict: true`, `skipLibCheck: false`, no workspace symlinks and no manually repaired SDK dependency list. Packages must agree on version 0.2.0. License/third-party notices must be included; the MIT license of our code does not replace dependency licenses.

## Model-quality gate

Use the unchanged, privately held Member and Live OAS snapshots selected on 2026-10-16. Supply all 176 candidates. Freeze six shorter scenarios and their verifier-only answers before calls: four executable scenarios and two clarification/missing-capability scenarios. Run each three times with the same model configuration and `maxRetries: 0`. This is a small known-contract follow-up cohort, not a held-out-service reliability estimate.

Do not infer or apply a numeric model-quality threshold. Measure how many executable first attempts meet the complete scenario oracle; negative cases must remain safely rejected or explicitly reviewable. Every executable result must have exact API choices, literal field values, response/native bindings and requested conditions, plus successful fixture execution including response changes or empty/duplicate arrays where relevant. A rejected first attempt stays in the denominator. No manual plan correction, post-hoc wording substitution, selected-case replay or evaluator correction may replace a failed original score. Report infrastructure/evaluator failures separately without silently dropping them. Owner review of these measurements remains pending before publication.

Report micro precision/recall for API call instances, literal input leaves, bindings and requested comparisons; exact-plan outcomes; gap/clarification accuracy; generation stage; runtime outcomes; latency; usage completeness and tokens. Missing fields/stages are not successful measurements. Unavailable usage and zero-denominator rates are null, not fabricated zeroes or perfect scores. Metrics do not authorize automatic semantic conversion.

## Publication boundary

Preparation produces release notes, migration/support guidance, verified package tarballs and an evidence report with explicit pass/fail/pending states. A failed gate or missing owner approval blocks publication. Never publish, create a release/tag or lower thresholds to make preparation appear complete. Publish the pinned verified artifacts only after a separate owner authorization and an immediate registry/version/identity check.
