# 0.2.0 model-quality measurement

Measured on 2026-10-16 against library implementation `7c081acfac295782e392853f2606dcc0857585a4`. This is evidence for owner review, **not a quality acceptance decision**. The owner explicitly deferred numeric thresholds until after seeing the results; no 90% gate was applied.

## Frozen evaluation

Two unchanged private service contracts supplied all 176 operation candidates. Six shorter natural-language scenarios ran three times each with the same host model configuration and automatic retries disabled. Expected API choices, literal values, bindings, comparisons and fixture responses were verifier-only. Four scenarios expected executable workflows; two expected clarification or an explicit missing capability. Generation called current public OSS stages composed by host LangGraph code; the library implementation was not changed for these trials.

This is a known-contract follow-up using task families already investigated during development. The shorter wording is new to this run, but the service contracts and task families are not held out. This sample is not sufficient to infer general production reliability, cross-provider behavior or unseen-service accuracy.

## First-attempt results

| Scenario family | Expected outcome | Matched outcomes |
| --- | --- | ---: |
| One API feeding four independent follow-up calls, then Merge/check | Executable workflow | 3/3 |
| Lookup response bound to a JSON-body update | Executable workflow | 3/3 |
| Two response-array split levels, detail lookup and condition | Executable workflow | 2/3 |
| Independent calls across both service contracts, then Merge/check | Executable workflow | 3/3 |
| Required identifier not supplied | Explicit clarification; no execution | 3/3 |
| Requested history capability absent | Reviewable gap; disconnected Start; no HTTP node | 3/3 |

Executable first attempts: **11/12 (91.7%)**. Negative handling: **6/6**. Combined expected outcomes: 17/18; the combined value must not replace the executable success rate. Thirty isolated n8n executions checked accepted plans with normal and changed responses, intentional business failures, reordered/duplicate arrays and empty arrays where applicable. Actual business services were not called.

One array-planning attempt interpreted “process duplicates too” as a need to identify/remove duplicates and reported an unavailable native deduplication capability. The frozen scenario required processing each duplicate unchanged. The native planner's gap caused a first-attempt failure. The original proposal remains in the private evidence; later independent repetitions did not replace it. No prompt-specific correction, output trimming, API replacement or model retry was added.

## Field metrics

These are micro counts across all twelve executable attempts. Precision counts correct accepted stage values divided by all returned accepted stage values. Recall divides by all frozen expected values, including values whose stage was never reached. A missing later stage is not scored as successful. Equality comparisons permit reversed equivalent operands; values are not coerced. Scenario-required capability coverage does not force one exact IF/assertion implementation.

| Decision | Correct / returned | Precision | Correct / expected | Recall |
| --- | ---: | ---: | ---: | ---: |
| API call instances | 36/36 | 100% | 36/36 | 100% |
| Literal input leaves | 15/15 | 100% | 15/15 | 100% |
| Output-to-request bindings | 19/19 | 100% | 19/21 | 90.5% |
| Requested comparisons | 25/25 | 100% | 25/27 | 92.6% |

The lost bindings/comparisons belong to the array attempt rejected before those stages. Precision alone therefore conceals a real end-to-end failure; it is not a release score by itself. This oracle measures these exact fields and runtime fixtures, not arbitrary schema implication or all possible business requirements.

## Usage and latency

The run made 92 real model calls. All 92 returned usage metadata: input 703,432 tokens, output 14,098 tokens, total 717,530 tokens. Mean model-call duration was about 2.32 seconds. Mean per-scenario generation-plus-execution durations ranged from about 5.28 to 29.88 seconds; these include intentional clarification/rejection and different numbers of runtime variants, so they are not directly comparable service latencies or an SLA.

Source OAS hashes, the frozen case hash, per-call timings/usage, all proposals, stage states, n8n JSON/logs, exact fixture requests and original failures are retained privately on the evaluation host. No provider endpoint, credential, private OAS, business identifier or raw model payload is included in this public summary. The scorer's focused tests cover duplicate penalties, stage omissions and literal type differences. The private evaluator's 46 unit tests, typecheck, lint and formatting passed.

## Publication decision

After receiving these results, the owner explicitly requested the 0.2.0 release under the documented host-review boundary. No numeric acceptance threshold was set or inferred. Known responsibility/clarification limitations, the false duplicate-related gap and mixed iteration/join execution scope remain recorded. Publication does not remove the failed attempt or turn upstream n8n contribution status into runtime evidence. See the separate [publication verification](0.2.0-publication.md).
