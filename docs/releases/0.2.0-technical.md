## Earlier preparation failures retained

The first full technical run remains a failed report. Two native-output checks lacked their required ICL regression OAS input. The runner now requires an explicit `--icl-oas` at its input boundary; it does not infer it from another OAS or filename.

The review probe incorrectly reconnected Start to an API fragment's logical **exit** (`Request ...`), which is now a response-decoder Code node. It bypassed the HTTP transport and failed before reaching the intended placeholder. The probe now takes the root call from the actual plan, recompiles its public HTTP fragment and connects to `fragment.entry`. It also identifies the placeholder by the plan's gap ID rather than treating the first Code node as a gap. A focused regression protects the entry/exit distinction.

The corrected real-n8n probe passed all five cases: four detached workflows sent no requests; the deliberately reconnected workflow sent one request, stopped at the actual gap and retained the expected error message. The original error-message assertion was not relaxed. This was an owned test-wiring correction, not an upstream error-display fix, changed library behavior or model-plan repair.

After these corrections, the full 26-check suite was rerun into a fresh artifact directory and passed. Original reports, logs and exact private inputs remain local; they are not copied into packages or this public summary.
