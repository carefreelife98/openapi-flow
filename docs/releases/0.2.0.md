## Repeatable technical check

Build inputs must be explicit. The original real-OAS regression requires its ICL/Honeypot regression corpus; use an appropriate private directory, not an arbitrary two-file substitution. The independent consumer separately accepts a selected actual OAS and an explicit operation/input JSON.

```sh
node scripts/verify-release-candidate.mjs \
  --oas-dir /absolute/path/to/private-regression-oas \
  --icl-oas /absolute/path/to/icl-regression.openapi.json \
  --consumer-oas /absolute/path/to/selected-service.openapi.json \
  --consumer-input /absolute/path/to/explicit-operation-input.json
```

The input JSON has this shape, with values supplied for the chosen OAS operation:

```json
{
  "operationRef": "#/paths/~1items/get",
  "argumentProposal": {
    "values": {
      "query": {
        "id": "explicit-synthetic-id"
      }
    }
  }
}
```

The command runs build/typecheck, lint/format, unit and real-OAS tests, the pinned isolated n8n regressions, strict installed-tarball consumer, dependency audit and package checks. It requires a working local Docker engine and registry access for the independent install. It never calls a model/business service, writes to remote n8n, publishes, tags or creates a GitHub release.

Each run writes `.local-artifacts/release-candidate/0.2.0-*/report.json`, individual logs and three verified tarballs. Every check's exit code is retained. Failure leaves `readyForOwnerReview: false`; model-quality approval always remains pending. A report from a different source revision or changed build input is not automatically valid for the current candidate.

- [ ] Decide numeric quality thresholds and whether this candidate meets them; document known failures and the limits of the sample.

- [ ] Approve release and npm publication separately. Until then, keep all three packages unreleased.

After approval, verify the signed-in registry identity, scope permissions, package/version availability and current authentication requirements. Publish the **verified** core tarball first, then langchain and n8n; both adapters depend on core 0.2.0. Recheck the registry versions and install from the registry in a fresh consumer. Do not overwrite an existing version, edit a tarball, skip failed checks or retry publication without checking the registry outcome. A Git tag/GitHub release is a separate external action requiring authorization.
