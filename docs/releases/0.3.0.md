# 0.3.0 release

Status: all three 0.3.0 packages published; public metadata and exact tarball integrities verified.

## Scope and ownership

Three matching libraries provide OAS catalogs/contracts and deterministic validation
(`core`), bounded model decisions (`langchain`), and official-SDK n8n compilation
(`n8n`). This release includes structured requirement clarification, canonical draft
changes/review, optional explanations, explicit gaps, input slots and the native
feature registry. It provides no HTTP server, UI, mandatory agent loop or automatic
business API execution. The private LangGraph example is a source reference, not a
fourth published package.

## Installation and migration

```sh
npm install @openapi-flow/core@0.3.0 @openapi-flow/langchain@0.3.0 @openapi-flow/n8n@0.3.0 @langchain/core@^1
```

Use Node.js 24 or later. Do not combine different minor versions of these three
libraries. Import domain types from public package exports; do not copy them or
use private source paths. The Core `/internal` entrypoint is an unstable adapter
boundary, not a host integration API. Core 0.1.0 used a different API; the existing
[0.2.0 migration](../migration-0.2.0.md) remains historical context.

Zod `^4.6.5` is a required shared peer, with 4.6.5 retained only as a development
pin. The earlier separate runtime pin conflicted with host Zod 4.6.7 schema types.
The corrected independent consumer uses TypeScript 6.0.3, Node types 24.19.2,
LangChain Core 1.2.18 and Zod 4.6.7, checks one actual Zod resolution across the
libraries, and passes strict declarations plus public workflow compilation. This
follows [Zod's peer-dependency guidance](https://zod.dev/library-authors#how-to-configure-peer-dependencies),
without casts, overrides or skipped declarations. A host that constructs Zod schemas
declares its own compatible Zod; modern package managers resolve compatible missing peers.

Hosts own LangGraph/checkpoint storage, sessions, transport, HITL policies, model
configuration and UI. They can compose the public primitives independently.
Persisted new canonical drafts include code-owned requirement history and scoped
receipts: do not fabricate these fields, silently migrate snapshots or rebase stale
approvals. Recreate state through the public constructors when adopting this
previously unreleased protocol. Native extensions must implement the declared
current contract/material-binding hooks; missing hooks fail explicitly.

## Accepted Ajv limitation

On 2026-10-19 the owner explicitly requested release with this limitation documented,
instead of an unapproved schema rewrite or dependency patch. Ajv 8.20.0 deliberately
excludes `__proto__` from its `properties` keyword processing. Generated validators
can reject a valid value as an additional property when `additionalProperties` is
false, or omit the declared property's constraints when extra properties are allowed.

This is not an OAS prohibition, an invalid JSON key, or evidence that existing
private OAS uses that name. Original OAS intake and data remain unchanged. Do not
rely on generated Ajv validation for contracts that declare `properties.__proto__`;
this release does not provide complete validation for that case. There is no
automatic field substitution, permissive retry or hidden compatibility transform.

The regression `prototype-looking JSON keys remain ordinary OAS data in runtime
slot assignment` stays enabled. Its failure is reported as an accepted release
limitation, never as a successful test. Any other deterministic test failure blocks
this release. Skipped, cancelled or incomplete tests are not accepted.

## Source reconciliation

The npm packages were published before their source changes were committed and
pushed. This was a release-process error, not an npm requirement. On 2026-10-20
the owner requested source synchronization before further product work.

The source reconciliation includes the three 0.3.0 package sources, matching
manifests and lockfile, public contracts, regression/integration tests, reference
LangGraph example and release documentation. Private OAS and local execution
artifacts remain excluded. Fresh build archives are compared with the already
published 0.3.0 integrities; this does not republish or alter that npm version.

For future releases the required order is: verify and review the source, commit,
push, confirm the exact remote commit, build/verify that committed source, then
publish the approved packages. The new source commit and remote result are
reported separately from npm publication. No Git tag or GitHub release is implied
by this reconciliation.
