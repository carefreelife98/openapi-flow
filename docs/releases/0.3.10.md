# 0.3.10 release

Status: verified source candidate, awaiting npm authentication and publication.
Public downloads and host installation have not been verified. The reviewed
source must be committed and pushed before publication.

## Changes

Reuse successful OAS value-validator compilation while running the original
Scalar validator for every supplied value. Normalization, dialect, source URI,
format checks, error reporting and request data remain unchanged. No validation
result, model output, request value or credential is cached.

The cache matches the complete normalized schema and original dialect, with a
deep equality check in addition to serialization. This avoids serialization-only
collisions. Caller-owned schemas and returned schema metadata cannot mutate the
private compiled resource. Failed compilation is not retained; its original cause
and current source remain visible.

Retention is limited to 64 least-recently-used entries and a total 1 MiB budget
for serialized schema keys. This is not an exact heap limit for generated
validator functions. Oversized schemas still compile and validate without being
retained. These internal retention budgets are not OAS acceptance limits.

## Verification boundary

The host's existing deterministic edit tests do not call a remote model. A CPU
profile from one worker attributed about 6.26 of 8.85 sampled seconds to Ajv
frames, including repeated `createOasValueValidator` compilation. This identifies
a substantial cost, not a complete attribution of every prior timeout.

Eight new regressions cover compilation reuse, independent schema copies,
changed schemas, original dialect/source isolation, per-value validation,
type/error preservation, bounded retention, oversized contracts, serialization
collisions and failed compilation. The first focused group passed 26 tests.
The unchanged owner-accepted Ajv `properties.__proto__` limitation remains a
release constraint. Full source, packed-consumer, n8n and post-install host
verification must be reported separately.

## Version-aligned checks

The candidate passed typecheck, all 54 original-OAS checks, 18 isolated local
n8n suites, strict independent packed consumption, all three package/archive
checks and a security audit with zero reported known vulnerabilities. Unit
results were 1,204/1,205 with only the unchanged accepted Ajv limitation and no
skipped or cancelled tests.

The initial gate retains a lint failure in the new test's explicit Node globals.
The test now uses the repository's `globalThis`/Node import convention; fresh
lint, format and all eight new regressions passed, including nested returned
schema mutation. A final `npm test` also completed with 1,204/1,205 and only the
same accepted failure. Its actual Node spec output was explicitly checked because
the follow-up tool expected TAP and rejected the reporter format. The actual
failure count was not changed to zero. Fresh lint, formatting and graph/document
checks passed, and all three rebuilt archives match the originally checked
SHA-512 integrities. Initial failing reports are retained unchanged; the final
assessment references their hashes and the separate successful checks.

Three isolated comparisons of 100 compile-and-validate calls each measured
348.06/301.78/300.91 ms with public 0.3.9 and 13.41/6.50/6.17 ms with the
candidate. Each pair produced identical full validation-result hashes for 50
valid and 50 invalid values, without changing input objects or string types.
This is a narrow compilation/validation measurement, not a host, browser or
end-to-end workflow performance guarantee.
