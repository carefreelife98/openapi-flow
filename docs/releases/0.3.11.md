# 0.3.11 release preparation

Status: owner authorized source-first publication and Qoopilot installation.
The candidate is not published. Source synchronization, npm publication and
post-install host/UI verification must be confirmed separately. No tag or
GitHub release is planned.

## Changes and ownership

With `selectOasEnums: true`, models select only actual OAS enum candidate IDs.
Core recomputes the current candidate inventory and copies the original JSON
value. Human intent, original OAS location and a short selection reason remain
separate from verbatim literal sources, independently of debug explanations.
Defaults and examples are not candidates and never become user intent.

Initial/add/replace draft argument planning, existing API value edits and
pending input replies use the common inventory. Existing-value edits select
IDs in their normal value call. Natural replies use the existing answer
extraction call, without regenerating the plan or value proposal.

Core exposes `describeWorkflowDraftApiInputEditAnswerRequirements`,
`resolveWorkflowDraftApiInputEditReply` and `validateApiInputAnswerAnalysis`.
Hosts retain original analysis rather than relabel semantic enum choices as
human-provided literals. Normalized OAS edit questions explicitly declare their
compiled schema dialect while retaining the actual source OpenAPI version.

The source reference LangGraph adds the explicit step/token-scoped
`reply-api-input-edits` command and reuses its existing extraction node.
Pending independent inputs keep the original atomic draft unapplied. Current
plan, pending targets, reply text, selected values and evidence are revalidated
before application. This example is host-owned source, not a mandatory server
or a published LangGraph runtime.

## Evidence before version alignment

The source passed 31 focused tests, including nine new edit-reply tests.
The complete suite finished with 1,238/1,239; the only failure was the unchanged
owner-accepted Ajv `properties.__proto__` runtime-slot limitation. No tests were
skipped, cancelled or converted to passing results. Typecheck, lint, formatting
and builds passed. Version-aligned results are recorded below.

An initial real-model edit request incorrectly selected removal of an existing
input when the user requested a question about its replacement. Both HTTP 200
model calls and the failed assertion/state are retained. Shared model and
structured-field descriptions now distinguish a pending replacement from an
explicit withdrawal. No lexical correction, changed model output or automatic
retry is introduced.

After that source change, the same request with the original OAS and actual
Chomsky made four HTTP 200 calls. Its natural answer copied the OAS enum value
while preserving the plan, API instance and original pending proposal.
The same result ran successfully in network-disabled n8n 2.37.10 against an
in-container loopback contract fixture: one expected request, original OAS
request/response validation, no ports/mounts/persistent volumes, and automatic
removal of the test container. No real business API was called.

## Remaining boundaries

These observed passes do not establish general semantic accuracy or unseen
service reliability. Complete nested/dynamic-target lifecycle coverage,
one-shot API convenience coverage, broader model evaluation and Qoopilot UI
integration remain separate work. The original Ajv special-key limitation is
still present; OAS documents and request values are not renamed or rewritten.

No external dependency version changes are intended. All three packages and
adapter Core dependencies are aligned at 0.3.11. The version-aligned archive,
independent-consumer, original-OAS, 18 isolated n8n suites and audit results
are recorded below. Publication and post-install host verification remain pending.
