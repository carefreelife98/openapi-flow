# 0.3.12 release

Status: candidate technical checks passed with the accepted limitation below;
not yet published or installed in Qoopilot.
The owner approved source-first synchronization, publication and exact-version
installation exceptions on 2026-10-23. Source commit/push, npm publication,
public archive verification and host integration remain separate evidence.

## Scope and ownership

Independent `generateApiArguments` now accepts optional `selectOasEnums` and
`trackRequestedInputs`. Enum interpretation enables requested-input tracking and
source-verified literals. First-call values must match actual scenario sources
without changing JSON types. Core derives remaining OAS enum questions and copies
the original value selected by candidate ID. Semantic choices and their intent
are kept separate from verbatim literal evidence and the original proposal.

Explicitly requested nested enum descendants can be described without inventing
their missing parent values or unrelated required inputs. Confirmed and bound
fields retain their original owners. There is no fake draft/edit plan, guessed
default, field removal, lexical correction, invalid-output retry or extra model
call when no actual enum question remains.

The source-only reference factories forward the two argument options and retain
`requestedInputs` during preparation checks. An unanswered requested optional
input is reported at argument preparation rather than reaching the graph-material
guard. That guard already rejected unresolved requests and is not relaxed.
Repeated roles retain independent values and receipts; provenance is not copied
into the later graph model's material projection. The confirmed-only conversation
mode and existing one-shot fail-fast behavior are unchanged.

The source suite passed 1,252 of 1,253 tests. The only failure was the unchanged,
owner-accepted Ajv `properties.__proto__` runtime-slot limitation. No tests were
skipped, cancelled or relabeled as passing. Focused factory, enum, partial-reply,
wire-schema and graph-document tests passed; original-OAS checks passed 54/54.
Builds, strict type checks, lint and formatting passed.

After corporate connectivity was restored on 2026-10-23, a fresh candidate run
with the original OAS completed operation selection, argument generation and enum
interpretation in three HTTP 200 Chomsky calls. Core copied the original enum
value and validated source/type evidence; SDK template compilation passed. There
was no automatic retry or business API call. This fresh result was not separately
executed in n8n or the host UI.

An earlier actual Chomsky run selected the original OAS operation and enum value.
The saved arguments were recompiled for an explicitly supplied loopback deployment
and executed successfully in isolated n8n 2.37.10 with original OAS request/response
validation. Source argument/template bytes and earlier timeout/assertion failures
were preserved. No business API was called. Factory regressions are deterministic
tests, not additional model-quality observations or execution of a host UI artifact.

## Release checks and publication

The version-aligned gate completed on 2026-10-23. Typecheck, builds, lint and
formatting passed. Unit results were 1,252/1,253 with only the unchanged accepted
Ajv failure; no tests were skipped or cancelled. All 54 original-OAS checks and
18 isolated n8n suites passed. Independent installation of the three candidate
tarballs passed strict public-type and runtime consumption. Audit reported zero
known vulnerabilities. All three archives passed metadata, exports, runtime
bundle inclusion, private-file exclusion and SHA-512 verification.

Only the eight intended workspace version references changed in the lockfile;
external resolutions and settings are unchanged. The gate inspected the working
candidate before its source commit. Source synchronization and a post-commit
rebuild/archive comparison must be verified separately before npm publication.
This gate does not prove that the packages are published or Qoopilot is updated.

## Limits

The existing Ajv special-key limitation remains enabled and documented. Original
OAS documents and request values are not renamed or rewritten. These checks do not
prove general semantic accuracy, unseen-service reliability, complete dynamic
target coverage or real business-service behavior. Webhook/callback and deferred
format/authentication extensions remain outside this patch.

Qoopilot still uses public 0.3.11 until all three new public package downloads are
verified. Its integration, UI review and download results must be recorded separately.
