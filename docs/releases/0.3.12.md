Status: all three packages published; public downloads verified.
The owner approved source-first synchronization, publication and exact-version
installation exceptions on 2026-10-23. Release source
`44a9b9a0f9ba86d34307b333029d6090dfaae5d8` was pushed to remote main before
publication. Source synchronization, npm publication, archive verification and
host integration remain separate evidence. No tag or GitHub release was created.

## Scope and ownership

Independent `generateApiArguments` now accepts optional `selectOasEnums` and
`trackRequestedInputs`. Enum interpretation enables requested-input tracking and
source-verified literals. First-call values must match actual scenario sources
without changing JSON types. Core derives remaining OAS enum questions and copies
the original value selected by candidate ID. Semantic choices and their intent
are kept separate from verbatim literal evidence and the original proposal.

Explicitly requested nested enum descendants can be described without inventing
their missing parent values or unrelated required inputs. Confirmed and bound
fields retain their original owners. There is no fake draft/edit plan, guessed
default, field removal, lexical correction, invalid-output retry or extra model
call when no actual enum question remains.

The source-only reference factories forward the two argument options and retain
`requestedInputs` during preparation checks. An unanswered requested optional
input is reported at argument preparation rather than reaching the graph-material
guard. That guard already rejected unresolved requests and is not relaxed.
Repeated roles retain independent values and receipts; provenance is not copied
into the later graph model's material projection. The confirmed-only conversation
mode and existing one-shot fail-fast behavior are unchanged.

## Separate host verification

The host enables the public initial-generation enum option and projects the copied
value and short reason through its existing shared view contract. Historical
initial receipts are not displayed for changed or removed owning calls. A new
deterministic regression checks partial input replies without repeating value
generation and rejection of modified receipts.

Host formatting, typed lint, strict types, 359 tests across 79 files and production
builds passed, as did separate API/web test-source type checks. The existing
965.19 kB initial JavaScript chunk warning remains.

One separate production-build UI case with the original OAS completed a short
ranking request, normal API and value review, approval and browser JSON download.
Actual Chomsky calls were five, all HTTP 200. Core copied the selected original
OAS enum; the downloaded bytes matched the server artifact. Reload preserved the
approved revision without another model call. Existing servers and user sessions
were not restarted or resubmitted.

No deployment address or credential was supplied, so this UI artifact has a
detached Manual Trigger and was not run in n8n or against a business API. It is one
observed case, not a general quality result. A verifier initially inspected the
wrong configuration level; the same unchanged downloaded bytes were rechecked at
the actual `arguments.values` location without another model call.

## Limits

The existing Ajv special-key limitation remains enabled and documented. Original
OAS documents and request values are not renamed or rewritten. These checks do not
prove general semantic accuracy, unseen-service reliability, complete dynamic
target coverage or real business-service behavior. Webhook/callback and deferred
format/authentication extensions remain outside this patch.

Host UI and complete multi-turn quality results must be recorded separately.
