# openapi-flow 0.3.14

Composable libraries for building n8n workflows from OpenAPI contracts with a
host-supplied LangChain model. Node.js 24 or later is required.

## Changes

- Add the shared `OpenApiFlowError` contract and the browser-safe
  `@openapi-flow/core/errors` entry point. Source-owned diagnostics distinguish
  model, contract and compilation boundaries while retaining original causes
  privately. Not every internal exception or provider timeout is migrated.
- Add `GatherApiResponses`: the model chooses actual call IDs, while code owns
  `{ results: [{ callId, documentId, method, path, body }] }` and preserves each
  complete response body. Repeated invocations retain distinct call IDs.
- Preserve initial enum-argument validation context without relabelling later
  transport failures, repairing values or adding retries.
- Apply supported Zod 4, Scalar parser, fast-uri and undici dependency updates
  without overrides or forced dependency replacement.

## Compatibility

Default native planning excludes legacy `ComposeApiResponses`; explicit legacy
selection and its original factory remain supported. Hosts with exhaustive
native-enum presentation maps must add `GatherApiResponses`. Saved workflows,
OAS contracts and response values are not migrated or rewritten. Hosts own
review, execution, localized error presentation and deployment.

## Verification and known limitations

Strict types, lint, formatting, 55 original-OAS checks, 19 isolated n8n suites
and an independent packed consumer passed. The full unit suite passed
**1,287/1,288**, with the existing accepted Ajv `properties.__proto__` case still
failing and no skipped or cancelled tests. The reference host passed 420 tests,
types, lint and build; deterministic browser checks verified normal/debug error
presentation. These checks do not establish broad model quality or diagnose a
historical production failure.

**Unresolved security advisory:** the production audit still reports five High
affected packages, all propagated from the same Zod 3 advisory
[`GHSA-mrhx-c7xc-m3w5`](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)
in the n8n SDK dependency chain. The owner explicitly accepted this disclosed
release risk. The advisory was not fixed, excluded or bypassed, and application
exploitability has not been established.

Webhook/callback expansion, operational streaming/shutdown, production log-sink
delivery and wider model-quality evaluation remain separate work. No service
deployment is included in this library release.
