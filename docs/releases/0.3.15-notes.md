# openapi-flow 0.3.15

## Packages

Keep `@openapi-flow/core`, `@openapi-flow/langchain` and `@openapi-flow/n8n` aligned
at 0.3.15. Node.js 24 or later and a compatible host LangChain model are required.

- [Core](https://www.npmjs.com/package/@openapi-flow/core/v/0.3.15)
- [LangChain](https://www.npmjs.com/package/@openapi-flow/langchain/v/0.3.15)
- [n8n](https://www.npmjs.com/package/@openapi-flow/n8n/v/0.3.15)

## Scoped binding planning

- `selectApiBindingSources` selects possible producers for one target from the
  complete discovery index. Code retrieves their unchanged original contracts.
- `planApiCallBindings` asks only for this target's actual field pointers and gaps.
  Target identities and binding kinds are supplied by code, not regenerated.
- Core's `assembleApiBindingPlan` requires every selected call and checks original
  OAS pointers/types, overlapping inputs and cross-call dependency cycles.
- `planApiBindingsByCall` provides explicit bounded concurrency, cancellation,
  cloned completion callbacks and validated same-input result reuse. Each stage
  is also independently composable in a host-owned LangGraph.
- Optional `callPlanning` receipts preserve producer-choice and field-choice
  reasons alongside the existing code-owned binding evidence.

The existing single-call `planApiBindings` API remains compatible. No arbitrary
API-count restriction, source pruning, field-name inference, value conversion,
output repair, hidden retry or timeout increase is added. Smaller jobs can require
more total model calls/tokens; they are not an arbitrary-scale quality guarantee.
Hosts retain ownership of persistence, review, orchestration and execution.

## Verification and limitations

Coverage includes 170 distinct operations across two OAS documents, per-call
checkpoint/resume, native sources, cancellation, actual HTTP tool schemas and
original whole-plan cycle/error regressions. A separate real-model five-API
probe produced ten bindings in eight requests; a large-catalog original-OAS
probe accepted a scoped 106,410-byte prompt. These did not execute live business
services or reproduce a historical failure's lost model response. A further
actual-model probe executed its API/native binding plans in isolated n8n:
three runs and eleven loopback requests passed, including changed upstream
values. The fixture, not the model, supplied those execution graph connections.

Strict types, lint, formatting, 55 original-OAS checks, nineteen isolated n8n
suite commands and an independently installed strict consumer passed. Unit
results were 1,297/1,298 with only the retained Ajv failure and no skipped or
cancelled tests. npm audit remains High 5 with the same previously accepted
dependency/advisory set as 0.3.14; the automated release gate therefore remains
blocked rather than reporting a clean audit.

The existing Ajv `properties.__proto__` limitation and the previously accepted
n8n SDK Zod 3 advisory
[GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)
remain disclosed, not fixed or excluded. Full release verification, provenance
and host status are maintained in the
[release record](https://github.com/carefreelife98/openapi-flow/blob/main/docs/releases/0.3.15.md).
Tag `v0.3.15` identifies the verified npm release source; service deployment is separate.
