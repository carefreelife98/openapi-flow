# 0.3.15 release

Status: source candidate verified with retained limitations; npm and GitHub
publication pending.
The owner authorized verified source-first patch publication and local host
installation. This does not authorize company-source push or Cloud deployment.

## Changes

See [scalable API binding planning](../scalable-api-binding-planning.md) and
[public release notes](0.3.15-notes.md). The compatible single-call planner remains;
the new public path scopes producer discovery and field planning to one target,
keeps every source discoverable, and assembles the whole plan with the original
coverage, pointer, type and global cycle validators. Call identities are code-owned.
Resource concurrency does not limit accepted OAS or selected API counts.

The owner supplies the LangChain model. Hosts may call each stage separately or
use bounded workers, cancellation and explicit same-input completed-call reuse.
No silent source pruning, field-name matching, data conversion, model-output
repair, hidden retry, timeout increase or new business API limit is introduced.
The shared per-call validator was extracted from the existing whole-plan validator;
the legacy validation messages/error codes and full-plan cycle checks remain.

## Focused and actual-model checks

The focused new/compatibility run passed 47 checks; an actual ChatOpenAI HTTP tool
probe passed one additional check, including JSON Schema 2020-12 meta-validation.
The 170-distinct-API/two-document regression passed with three bounded workers and
339 small model-fixture invocations. Eight actual Chomsky requests planned ten
bindings across five public-fixture API calls with no gaps or value conversion.
A private original-OAS regression completed all 170 call results with 162 producer
choices and zero field calls for its explicitly independent scenario. Its maximum
discovery input was 106,294 bytes versus the old 428,340-byte whole-plan context.
The original input documents remained unchanged. A separate real Chomsky probe on
the largest request schema in that inventory accepted a 106,410-byte prompt in
5,009 ms and needed no field-planning call. Neither probe executed business APIs.

These are different cohorts, not a replay of a historical failed 170-call model
response and not proof of arbitrary-scale semantic accuracy. Current source
snapshots need not match that historical deployment.

A separate actual Chomsky run used the new planner for both API and native
bindings, then compiled and executed the result in isolated n8n 2.37.10. Two
five-API runs changed the first response at runtime and verified downstream
requests used that changed value. A third run bound a native output to an API.
All three executions and eleven loopback HTTP requests passed. The fixture
supplied topology and native configuration; this is not a claim that the model
designed the entire DAG. Business-service requests remained zero. Planning
receipts were preserved privately and absent from generated workflow JSON.

only the retained Ajv special-key failure; skipped and cancelled counts were zero.
Original OAS checks passed 55/55. All nineteen isolated n8n suite commands and an
independently installed three-archive consumer passed. The consumer checked new

the owner previously accepted; no external dependency version or exclusion
changed. This is not a clean audit. The existing Ajv failure is also retained,
not skipped or repaired. Public archive provenance and host integration are
recorded only after those steps actually complete.

## Retained limitations

The existing Ajv `properties.__proto__` failure remains enabled. The n8n SDK's
Zod 3 chain retains the previously accepted advisory
[GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5);
this patch changes no external dependency versions or audit exclusions.
Provider limits, total token/latency costs, final orchestration quality and
operational streaming/shutdown remain separate concerns. API-level receipts are
not a finished workflow; complete coverage and global checks remain mandatory.
