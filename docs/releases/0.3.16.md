# 0.3.16 release

Status: all three npm packages and
[GitHub Release v0.3.16](https://github.com/carefreelife98/openapi-flow/releases/tag/v0.3.16)
published on 2026-10-25. Public archives match the verified source. The owner
authorized source synchronization, this release and local host installation,
not company-source push, Cloud deployment or restarting an existing in-memory
conversation server. Host installation is separate from actual new-planner/UI integration.

## Changes and compatibility

See the [public notes](0.3.16-notes.md) and [connection guide](../incremental-connection-planning.md).
The new Core session API and separate model goal/step functions are additive.
Existing complete-plan validators and single-pass APIs remain. Native generation
adds an optional AbortSignal without requiring a new host runtime. The private
example is a host composition, not a new mandatory framework or npm package.

Goal/session/call identities, single-port mapping and source receipts are code-owned.
The model chooses semantic roles, endpoints, multi-port routes and connection
bundles. Code checks each bundle atomically and preserves rejected state. The host
controls repeated semantic replanning under explicit budgets; HTTP/model failures
do not trigger hidden retries. Only genuine business uncertainty can request review.
No API-count cap, source pruning, input invention, response-field renaming or data
conversion was added.

## Actual model and engine cohort

The native-augmentation fixture supplied five API instances and their exact OAS
contracts/bindings, but no prepared join. One actual-model run generated a join and
three accepted bundles: six calls (one goal, four connection, one native-settings),
one native node, zero rejected proposals. The unchanged generated JSON ran in
isolated n8n 2.37.10. Two fixed-baseline executions and two generated executions
passed twenty loopback HTTP requests. Arrays, numeric zero, Unicode and a literal
starting with `=` were preserved. No business-service API was executed.

Two earlier actual-model attempts hit the unchanged rejection budget: ten model
calls in the first and nine in the diagnostic run. The first attempt's exact
rejection cause is unproven. The diagnostic run proved an implementation defect:
ordinary path dominance treated another required join input as a producer bypass.
The fix reuses the existing full topology analyzer's route proof. Compatible
all-input branches union completed producers/outputs; alternatives remain separate.
Regression tests cover each branch's precedence, direct bypass rejection,
exclusive-route rejection and public inspection serialization. No model output was
edited and the call/rejection/deadline budgets were not raised for the successful
rerun. All attempts remain private evidence; failed runs are not counted as passes.

This is not an old-versus-new model latency/quality benchmark, a real parallelism
measurement, a short-query API-selection evaluation or arbitrary-scale proof.
Broader original-OAS model and host UI cohorts remain separate work.
