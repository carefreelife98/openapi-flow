## Scope and compatibility

See the [public notes](0.3.17-notes.md) and
[connection guide](../incremental-connection-planning.md). The new Core discovery
projection and LangChain goal-rejection classifier/schema/type are additive.
Goal calls remain single invocations. Automatic iteration belongs to the host
reference, whose shared resource budgets now include initial goal rejections.
Original rejected outputs and reasons remain private checkpoint evidence.
Source changes, transport failures, cancellation and non-JSON output never enter
this replanning path. Invalid goals never enter a partial connection session.

Clarification receives the entire discovery inventory rather than raw sibling
operations and native settings schemas. The full canonical contracts still own
later generation, evidence and validation. This is a stage boundary, not OAS
pruning, a schema rewrite or a limit on supported APIs.
