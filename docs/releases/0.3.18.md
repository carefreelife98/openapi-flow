# 0.3.18 release

Status: verified candidate; not published. The owner authorized reviewed source-first
commit/push, the matching annotated tag, all three npm packages, GitHub Release and
local host installation. Company-source push, Cloud deployment and restarting the
original in-memory server are excluded.

## Cause and fix

A fresh actual-model browser run on public 0.3.17 failed before connections at
per-call API bindings. The model described a required value as independent input
but also reported its absent upstream producer as a binding gap. Independent
request values belong to the subsequent argument/question stage. The old flat
source-ID and gap arrays allowed that contradictory output.

The new internal structured schema has four literal-kind decisions. The mapper
constructs only the fixed empty arrays implied by a validated decision. It never
repairs raw model output or discards genuine gaps. The provided-source branches
are available only when actual candidates exist. Partial source availability is
preserved rather than restricting support to all-or-nothing cases. Existing Core
resolution still checks source identities and original request pointers.

An initial Zod discriminated-union candidate emitted `oneOf`; the actual provider
rejected it with `invalid_function_parameters` / HTTP 400. A Zod union with distinct
literal kinds now emits `anyOf`, without post-conversion JSON Schema rewriting.
All failure records remain private. No private OAS, checkpoint, model output or
company code is included in the public release.

## Verification, 2026-10-26 KST

Strict types, lint and formatting passed. Four added regressions plus the existing
per-call HTTP/checkpoint/cycle/cancellation/170-call cases total fourteen focused
tests. The complete suite passed 1,378/1,379; the sole failure is the previously
accepted, enabled Ajv `properties.__proto__` case. Skipped/cancelled counts are zero.

The complete original private OAS cohort passed 56 checks. The first attempt used
a repository directory without the required ICL snapshot and failed for absent
verification inputs. That result remains; the complete previously used cohort was
then explicitly selected, with no source document or product validation change.

The request-binding runtime suite passed two successful data scenarios and two
expected rejections in isolated n8n 2.37.10, totaling twelve loopback requests.
Incremental connections and native augmentation each passed four executions and
twenty loopback requests. No business-service API was called. These three relevant
runtime suites were rerun; this is not a new rerun of all twenty-one 0.3.17 suites.

Independent installation used all three packed 0.3.18 packages, no workspace links,
strict TypeScript with dependency checks enabled, and the matching original member
OAS/input fixture. It compiled workflows over 154 supplied operations. Three actual
provider trials reused the failed binding-stage input unchanged; each retained all
five selected API calls and returned no invented upstream dependencies. That checks
this stage only, not an end-to-end browser recovery or semantic accuracy in general.

The audit still reports High 5. Advisory/dependency records match 0.3.17 after
excluding only `fixAvailable` suggestions. External dependency versions are unchanged.
The unresolved Ajv and SDK Zod 3 risks are not hidden, excluded or described as fixed.
The broad clarification timeout and mid-render/viewport evaluation remain open.
