# 0.3.3 release

Status: owner authorized source-first publication and installation of the exact
three 0.3.3 versions. Versioned technical checks are complete with the retained
Ajv limitation below. Source synchronization and publication are not yet claimed.

## Changes

Existing API input edits now use the same plan's explicitly staged operation
replacement and completed materials. Input contracts bind to the stage
fingerprint. Unresolved source replacements remain blocked; the original draft
is not mutated or prematurely approved.

Core exports `workflowDraftApiInputEditAnswersSchema` for the transport shape and
`createWorkflowDraftApiInputEditAnswersSchema` for current-contract, pending-target
and original-OAS value validation. Pass actual typed user replies through
`confirmedAnswers` to `resolveWorkflowDraftApiInputEdits`. The unchanged model
proposal and separate human receipt are retained. Partial replies do not apply
partial transactions. Stale IDs, duplicate targets, extra fields, wrong types and
invalid complete requests are rejected without coercion or synthetic messages.

The source-only LangGraph example emits typed `api-input-edit` questions and
accepts `answer-api-input-edits`, preserving checkpoint state, final review,
source evidence and original drafts. Direct value replies do not repeat the
semantic/target/value model calls. Host applications still implement their own
forms, review policy and session storage; installing a package is not UI work.

Optional user-facing edit explanations now request the current user's language.
Identifiers, actual values and source quotations remain unchanged. There is no
translation call, output repair, language-based validation gate or hidden retry.

## Verification scope

Before the version bump, the complete regression run was 1163/1164 with the one
previously accepted Ajv failure. Original private OAS checks passed 52/52, and an
independent three-tarball consumer passed strict TypeScript with
`skipLibCheck: false` and no workspace symlinks. Actual HTTP-wire tests checked
the model instructions and schema descriptions.

Two separately retained actual-model evaluations each used the full original
34-operation ICL catalog, 11 model calls and four versions of one conversation.
Each version executed in isolated n8n 2.37.10 against a local OAS contract server.
Typed replies preserved a leading-zero string through actual HTTP and made no
additional value-planning calls. The first run exposed three English display
reasons; after the source instruction fix, all twelve observed reasons contained
Korean. This is one known conversation cohort before/after a fix, not eight
independent scenarios or a general quality/language reliability score. Test
approvals, response data and local credentials were synthetic. No actual
business API or company n8n instance was called.

Final 0.3.3 build, workspace typecheck, lint, format, whitespace and source-derived
graph checks passed. The complete versioned regression run was 1163/1164, with
only the unchanged accepted Ajv failure, no skips and no cancellations. Original
private OAS checks passed 52/52. The strict independent consumer installed the
three 0.3.3 tarballs, compiled with `skipLibCheck: false` and exercised the new
public answer boundary against the full original ICL snapshot without workspace
symlinks. The isolated n8n request-binding matrix passed all four cases and the
deployment-template matrix passed. These are focused patch checks, not a fresh
run of every historical matrix or a new model quality measurement.

Source synchronization and publication receipts will be recorded separately.

## Retained limitation

Ajv 8.20.0 does not correctly validate a declared `properties.__proto__`.
Generated validation may reject valid data or omit that property's constraints.
The owner previously accepted this release limitation; the original regression
remains enabled and failing, not skipped or counted as passed. No field rename,
value rewrite, schema compatibility transform or failure suppression is included.
See the [original limitation](0.3.0.md#accepted-ajv-limitation).

All three packages and adapter core dependencies are aligned at 0.3.3. Node.js
24+, Zod and LangChain peer requirements and n8n dependency licensing are unchanged.
