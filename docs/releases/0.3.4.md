# 0.3.4 release

Status: release preparation. Source synchronization, npm publication and public
host installation have not yet completed for this version.

## Changes

Optional review follow-ups now label the supplied review boundary as
`review-material-not-user-intent`. Pending questions, proposed APIs and candidate
drafts are not confirmed requirements. Model instructions and Zod descriptions
distinguish those materials from actual messages and confirmed answers, request
the user's language and keep internal bookkeeping in structured evidence instead
of user-facing sentences. Original values, quotations and real API identifiers
remain unchanged.

This corrects the model input at its owning source. It does not sanitize output,
rewrite source quotations, ban OAS fields, add a translation call, retry a failed
proposal or automatically adopt a suggestion. It is an instruction improvement,
not a deterministic guarantee of semantic accuracy or absence of internal IDs.
Public types, revision/fingerprint checks and explicit adoption are unchanged.

The three packages and adapter core dependencies are aligned at 0.3.4. The n8n
adapter has no implementation change in this patch. Node.js, Zod and LangChain
requirements and dependency licensing remain unchanged.

## Verification scope

The pre-fix actual-model observation used published 0.3.3 in a separate host with
an unchanged private 34-operation catalog. A review suggestion attributed an
unapproved cache lookup assumption to a short generic product-information
request and exposed an internal candidate ID. That observation is retained as
a quality failure, not counted as a pass. No actual business API was called.

The new HTTP-wire assertions failed before the correction and passed afterward.
Focused Core, ChatOpenAI-wire and MemorySaver tests passed 9/9. The host's final
pre-install verification passed 63 test files and 273 tests, strict typechecks,
typed lint, formatting and production builds. Those are implementation checks
against the previously published libraries, not a new post-fix model evaluation.
Final versioned build, workspace typecheck, lint, formatting and source-derived
graph checks passed. Full regression was 1163/1164 with only the original
accepted Ajv failure, zero skips and zero cancellations. Original private OAS
checks passed 52/52. An independent consumer installed all three matching 0.3.4
archives, compiled with strict TypeScript and `skipLibCheck: false`, and exercised
public contracts with the full unchanged 34-operation catalog, without workspace
symlinks or business API calls. The focused follow-up adoption conversation also
executed in isolated n8n 2.37.10 against a synthetic local contract server. This
was a deterministic model fixture, not a new actual-model quality result or a
fresh run of every historical n8n matrix. Post-publication verification and a new
actual model/browser evaluation remain pending.

## Retained limitation

Ajv 8.20.0 does not correctly validate a declared `properties.__proto__`.
Generated validation may reject valid data or omit that property's constraints.
The owner previously accepted this release limitation; the original regression
remains enabled and failing, not skipped or counted as passed. No field rename,
value rewrite, schema compatibility transform or failure suppression is included.
See the [original limitation](0.3.0.md#accepted-ajv-limitation).

The host still owns suggestion UI, explicit adoption, review policy and sessions.
This patch does not establish general workflow/model quality or complete those
host responsibilities. No source tag or GitHub release is implied by npm
publication.
