# 0.3.4 release

Status: all three packages published. Public metadata, latest tags and downloaded
archive SHA-512 match the independently tested files. Public host installation
and its 273-test verification passed. The new actual-model follow-up evaluation
exposed a retained display-quality failure, documented below.

## Changes

Optional review follow-ups now label the supplied review boundary as
`review-material-not-user-intent`. Pending questions, proposed APIs and candidate
drafts are not confirmed requirements. Model instructions and Zod descriptions
distinguish those materials from actual messages and confirmed answers, request
the user's language and keep internal bookkeeping in structured evidence instead
of user-facing sentences. Original values, quotations and real API identifiers
remain unchanged.

This corrects the model input at its owning source. It does not sanitize output,
rewrite source quotations, ban OAS fields, add a translation call, retry a failed
proposal or automatically adopt a suggestion. It is an instruction improvement,
not a deterministic guarantee of semantic accuracy or absence of internal IDs.
Public types, revision/fingerprint checks and explicit adoption are unchanged.

The three packages and adapter core dependencies are aligned at 0.3.4. The n8n
adapter has no implementation change in this patch. Node.js, Zod and LangChain
requirements and dependency licensing remain unchanged.

## Public host and actual-model observations

The separate private host installed the three exact public 0.3.4 packages, without
local tarballs or source substitution. Only the owner-approved exact three
release-age exceptions were added; the strict 1440-minute policy and other
registries remain unchanged. Supply-chain checks and frozen-lockfile installation
passed. Host formatting, typed lint, strict application/test typechecks,
63 test files / 273 tests and production builds passed. The existing large initial
JavaScript chunk warning remains.

A fresh isolated host process verified its installed public versions before an
actual-model/browser conversation using the unchanged initial request and original
34-operation catalog. This run asked a lookup-method question; the earlier run
did not. The clarification implementation was not changed by this patch, so that
variation must not be attributed to the follow-up instructions. A synthetic
test-driver reply explicitly selected the offered detail-lookup option.

Two optional follow-up calls were evaluated, with four model calls total. All
three clarification suggestions exposed internal question IDs in their text:
**display quality failed** despite the new instructions. At selection review, one
suggestion contained no internal ID, and its reason explicitly distinguished the
unconfirmed cache lookup from the user request. This is one scoped observation,
not proof of general attribution accuracy. API selection still proposed a cache
lookup after the detail-lookup reply; that candidate was not approved. No workflow
was exported and no business API or new n8n execution occurred in this host case.

Concurrent/repeated reads and a browser reload made no additional model calls or
workflow mutations. Wrong revision, interrupt and namespace returned 409; an extra
request field returned 400. The original approval controls remained available,
reason/evidence were debug-only, and browser error/warning logs were empty. Original
memory servers and failed observations were preserved. No output sanitization,
rewritten evidence or hidden retries were used to turn the failure into a pass.

User-facing ID-free suggestions, typed explicit adoption at unfinished host review
boundaries, broader API-selection quality and streaming/load work remain open.
The patch is published and installable; the overall product/quality goal is not
complete.

## Retained limitation

Ajv 8.20.0 does not correctly validate a declared `properties.__proto__`.
Generated validation may reject valid data or omit that property's constraints.
The owner previously accepted this release limitation; the original regression
remains enabled and failing, not skipped or counted as passed. No field rename,
value rewrite, schema compatibility transform or failure suppression is included.
See the [original limitation](0.3.0.md#accepted-ajv-limitation).

The host still owns suggestion UI, explicit adoption, review policy and sessions.
This patch does not establish general workflow/model quality or complete those
host responsibilities. No source tag or GitHub release is implied by npm
publication.
