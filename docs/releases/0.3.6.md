# 0.3.6 release candidate

Status: preparation in progress; not published. Source synchronization, independent
archive verification, npm publication and host installation are separate gates.

## Changes

- Accept explicit human text for original single-/multiple-choice requirement
  clarification questions without converting it to a choice or rewriting evidence.
- Add public, source-bound `WorkflowReviewFeedback` schema/type and receipt APIs.
  Review/question scope is explicit; stale identities/revisions, unknown questions,
  blank text and mixed approval/choice/value fields fail before resume.
- Preserve deterministic choice/value/approval paths. Feedback invokes no model,
  approves nothing and applies no graph edit. Hosts own semantic replanning,
  checkpoint policy, canonical draft replacement and UI composition.
- Align all three packages and their internal dependencies at 0.3.6. No service
  fixture, guessed selection, schema coercion, automatic retry or new SDK override.

## Verification boundary

Focused clarification, feedback identity/provenance and real MemorySaver resume
tests pass. The checkpoint fixture checks a zero-planner-call explicit choice,
one explicit feedback-triggered replan, stale resume rejection followed by a valid
resume, and waiting for a new human choice rather than auto-approval. Its planner
is deterministic, not a live model quality evaluation.

The final library unit run has 1,182 tests: 1,181 pass and the one owner-accepted
Ajv limitation fails, with no skipped or cancelled tests. Typecheck, lint, format
and source-derived graph checks pass. All 52 original-OAS checks, 17 isolated n8n
integration suites and the dependency audit pass. The independent packed consumer
installs all three 0.3.6 archives without workspace symlinks, omits development
dependencies, typechecks without skipped library declarations and runs the public
feedback assertions. Its three archive integrities match the candidate archives.

The first candidate report is retained as failed: it included an obsolete test
expectation that custom text was invalid, plus a consumer invocation using an input
file for a different OAS. The original-source expectation was corrected and the
whole unit suite rerun; the consumer was rerun with the existing matching ICL input.
No OAS, request value or consumer implementation was rewritten to make it pass.

These are library, checkpoint and isolated execution checks, not proof of the
separate host's new UI or semantic replanning. Remote source synchronization,
public npm archive verification and actual host installation remain pending.

The owner-accepted Ajv 8.20.0 `properties.__proto__` limitation remains unchanged.
Its original regression stays enabled; no OAS or data key is renamed or rewritten.
Other 0.3.x model-quality, advanced execution and host lifecycle limits remain.
