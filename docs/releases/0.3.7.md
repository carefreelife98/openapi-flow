# 0.3.7 release

Status: candidate; not yet published. Source must be committed and pushed before
publication. Library, registry download and host verification are separate steps.

## Changes

- Add explicit `operation-multiple-choice` API questions with required minimum and
  maximum selection counts and an `operations` answer envelope.
- Preserve the original `operation-choice` / `operation` exactly-one contract.
  Never infer selection mode, counts or execution order from natural-language prose.
- Export synchronous `resolveApiOperationChoiceAnswer` and
  `validateApiSelectionQuestion` boundaries. Enforce bounds, distinct offered keys,
  matching question identity and answer shape without invoking a model.
- Extend model structured output and the host-owned LangGraph example. The complete
  catalog resolver retains current-snapshot validation and partial-answer behavior.
- Align all three public packages and internal dependencies at 0.3.7. No company
  source/OAS fixture, credential, guessed choice or local SDK substitution is added.

## Verification boundary

The final library unit run has 1,189 tests: 1,188 pass and the one owner-accepted
Ajv limitation fails, with no skipped or cancelled tests. Typecheck, lint, format
and source-derived graph checks pass. All 53 original-OAS checks and 17 isolated n8n
integration suites and the dependency audit pass. The strict independent consumer
installs all three archives without workspace symlinks, typechecks with no skipped
library declarations and exercises the new public choice contracts. Registry and
complete host verification are still pending; no publication is claimed.

The initial real-OAS regression incorrectly assumed every individual source had at
least four operations. The corpus includes a one-operation document. The test was
corrected to offer four actual operations from the combined, unchanged catalog,
then the entire original-OAS suite was rerun. The earlier failed candidate report
is retained rather than relabeled as passing.

An actual OpenAI-compatible provider rejected the initial discriminated union's
`oneOf` output. Defining the same literal-tagged, disjoint branches with Zod
`union` produces the supported `anyOf`; no JSON Schema rewrite, loose parse or
hidden retry was added. The wire regression checks both branches, explanations,
strict schema validity and absence of `oneOf`. A separate post-fix provider call
using an unchanged original OAS produced a four-candidate question with bounds
3..4. Core applied three selected keys without another model call. The first HTTP
400 is retained. Neither this probe nor the browser form test calls business APIs
or proves general semantic accuracy.

The owner-accepted Ajv 8.20.0 `properties.__proto__` limitation remains unchanged.
Its original failing regression stays enabled. Other model-quality, execution and
host lifecycle limits remain; selection metadata does not prove semantic quality.
