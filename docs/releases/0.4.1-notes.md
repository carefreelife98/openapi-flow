## Source-grounded request inputs

Optional `literalSourceMessages` supplies the original `WorkflowSourceMessage`
records independently of formatted `scenario` context. Exact literal citations,
message identity, value types and coverage are checked against those records.
The code does not unwrap arbitrary JSON or combine separate original messages.

Enum interpretation uses the same explicit original sources. The model selects
existing OAS candidate identities and source spans; code copies the original OAS
value without changing its type. A valid source span does not prove that the model
understood its business meaning. Callers remain responsible for supplying genuine
original messages rather than generated summaries.

## Scoped recovery

Native selection and gap review accept explicit same-request contract rejections.
Helpers retain the original invalid output and validation reason only when its
source fingerprint and stage still match. Transport errors, cancellation and source
changes are not corrective proposals. Each library call still runs once. The
optional example graph checkpoints rejections and charges every correction to its
existing shared invocation limit; genuine unsupported work and business questions
are not automatically bypassed. Existing mid-run example checkpoints without the
new rejection ledger must not be silently migrated.

API material repair accepts a separate original literal context and validates its
target and original contracts. Existing native dependency/parameter repair preserves
node identity and declared ownership, re-derives output contracts and checks downstream
references. These are composable functions, not a hidden retry or user-interrupt policy.
The example preserves repair descriptions in serializable checkpoints and receives
executable contracts through runtime configuration.

## Compatibility, verification and limitations

The new source context is optional. Existing reply-only callers retain their output
shape; callers opting into explicit messages must preserve original message identities
and citations. No external dependency version changes are included.

Release verification is in progress; consult the detailed release record before
publication. The enabled Ajv `properties.__proto__` limitation and previously disclosed
upstream SDK Zod 3 advisories remain unresolved. No clean audit or complete
natural-language workflow quality result is claimed. The original five independent
single-pass/incremental scenario comparison and private-host recovery integration
remain unfinished. This release does not deploy a company service.
