# 0.4.3 release record

Status: authorized candidate, not yet published. The owner authorized verification,
personal OSS source synchronization first, an annotated matching tag, three npm
packages, GitHub Release and public local Qoopilot installation. Company push,
Cloud deployment and existing user-server restart are excluded.

## Cause and scope

In 0.4.2, `not-provided` meant that no literal had been supplied. The scheduler
nevertheless sent all unanswered OAS enum questions to a second semantic model
call. Thus an unknown input could be filled from an illustrative value even after
the first call had correctly left it empty. A prompt-only experiment did not fix
that scheduling contract and was not published.

0.4.3 adds an explicit functional `enumIntentInputs` list to the opt-in initial
output. The model identifies actual supplied natural-language value intentions;
code validates and schedules only those targets. Empty intent skips the second
call. Required unknown inputs remain unresolved for host questions or explicit
runtime slots. Reasons are display metadata, not branch conditions. OAS and typed
literal/source/binding/ownership checks remain intact. No private API names,
example values, text matching heuristics or automatic substitute values are added
to production code. The API and enum contracts belong to Core, invocation and
schemas to the LangChain adapter, and conversation/deferral/UI to the host.

## Actual-model evidence

Two controlled input-stage checks used an actual selected contract and unchanged
original scenario, then a separate explicit local fixture confirmation. The first
left its required enum absent; the second preserved the supplied exact value.
Durations were 10.224 and 3.756 seconds. Four model HTTP requests comprised two
429s and two successes under the existing provider routing. No second semantic
call, engine run or business-service request occurred. These checks reused a
selected contract and are not fresh end-to-end generation evidence.

A separate fresh product graph ran the unchanged original multi-OAS scenario from
the start, without prior material reuse. The diagnostic composition used public
0.4.2 host planners with only the explicitly injected candidate argument planner;
it is not a public 0.4.3 installation or production deployment. The input stage
left the example value absent and the host accepted explicit runtime deferral.
The run stopped in connections after 199.862 seconds: Merge configuration required
ten inputs, while the model connected only three service aggregates. No JSON or
engine success is claimed. Thirteen model HTTP requests comprised ten 200s and
three 429s handled by the existing routing policy. Ten responses reported 231,484
input and 9,547 output tokens; missing usage was not estimated. The original
failed result is retained privately.

## Release checks

The versioned source passed root typecheck/build, Lint and format. The enabled
`npm test` suite passed 1,796 of 1,797 tests, with only the retained Ajv regression
and no skips, cancellations or todo cases. The full runtime suite took 172.494
seconds. Graph/release checks passed 11 tests and four original private OAS
documents passed 59 checks. Private inputs remain outside the release source.

Two isolated n8n 2.37.10 suites covered requested inputs and response bindings.
Eleven executions comprised five successes and six intentional missing/invalid
input stops; 17 HTTP requests reached local fixtures only. Unknown runtime inputs
were not replaced with values. Explicit false values and response types were
preserved. Temporary owned workflow volumes were removed. These are engine
contract checks with synthetic data, not actual-model planning quality.

The independent consumer installed three packed archives without workspace links
or skipped library checks, passed strict compilation and ran against an original
ICL snapshot with 34 operations. This does not substitute local archives into
Qoopilot. All three final archives passed package/export/notices/private-artifact
checks and local SHA-512 verification. Source synchronization, public archive
verification and GitHub publication remain required. External dependency versions
are unchanged. The current audit reports High 5, with all
other severities 0, on the upstream SDK dependency path. This is not a clean audit.

## Known limitations

The enabled Ajv `properties.__proto__` regression is the previously disclosed
external limit; original OAS and request data are not rewritten. The previous
and current audits both report five High upstream SDK findings.
Model semantic classification, separate Merge planning, full UI verification and
the independent original-five single-pass/incremental comparison remain open.
