# 0.4.4 release record

Status: versioned release verification completed; publication pending. The owner authorized personal OSS
source synchronization first, an annotated tag at that exact source, the three
npm packages, a published GitHub Release and public local Qoopilot installation.
Company push, Cloud deployment and existing user-server restart are excluded.
No npm publication or installed 0.4.4 is claimed by this preparatory record.

## Responsibility and behavior

Core owns original source lookup, replay identity and canonical contract checks.
LangChain owns the ID-only model output protocol and native role context.
Qoopilot owns timeout policy, conversation handling and forwarding its chosen
full-role review mode. The latter host fix preserves the original reviewed gaps
and makes no new model call. It does not approve unsupported behavior.

Clarification previously required display reasons/evidence at runtime whenever
explanations were requested. An otherwise valid requirement could therefore fail
on presentation alone. The wire schema still guides the model, while canonical
parsing permits absent display information. Any supplied message, OAS or native
reference is validated before optional display omission. Functional statements,
choices, bounds and original source ownership remain strict. A real LangChain
client against a local HTTP fixture covered eight calls, including retained
unknown-reference/required-source failures and HTTP 503 propagation, without
explanation retries. This is not an actual Chomsky quality check.

The tracked-literal wire schema no longer asks the model to copy `sourceText`.
Code catalogs original complete JSON tokens; the model selects a candidate ID.
Code then resolves and verifies the exact typed value and full target coverage.
Unquoted string proposals use their exact value as the checked source text.
Initial enum decisions separately represent missing meaning or selection of an
original OAS candidate. Code-owned source fingerprints do not depend on display
reasons. Existing human-answer extraction is not replaced with this initial-input
protocol. No scenario names, service IDs or fixture values are hardcoded into
production logic, and no runtime value is filled merely to obtain a passing run.

## Actual-model and engine evidence

Ten independent fresh runs used five unchanged original scenario/OAS pairs,
separate threads/checkpoints and alternating mode order. Each model request had
an explicit 180-second limit; bounded native and connection budgets remained.
All ordinary planners were public 0.4.3; exactly two candidate functions were
explicitly supplied. No old plan was reused across modes, no business answer was
fabricated and no initial technical failure was retried.

| Outcome                     | Single-pass | Incremental |
| --------------------------- | ----------: | ----------: |
| Generated SDK JSON          |           1 |           0 |
| Technical failure           |           1 |           0 |
| Clarification wait          |           3 |           5 |
| Reached connection planning |           1 |           0 |

The technical failure was the host's omitted full-role-review option. Replaying
the saved state after its local fix preserved the original three gaps and
returned the intended reviewed-gap contract, with zero new model calls. That is
not a fresh successful whole-workflow generation.

The successful original operations scenario generated ten GET APIs, three
aggregates, one Merge, thirteen logical edges and forty-four physical n8n nodes
on the first attempt in 256.386 seconds. Fifteen model HTTP requests comprised
ten 200s and five 429s under the existing provider routing; reported usage was
231,895 input and 9,572 output tokens. Unreported usage was not estimated.

The exact generated JSON, not a regenerated plan, ran on isolated n8n 2.37.10.
Only explicit local deployment configuration and the Start link were changed
using the SDK; every non-Start edge and all business parameters stayed intact.
Ten local GETs yielded three service groups with 5/3/2 original responses and
three final Merge items. Original values, types and provenance were checked.
Synthetic OAS-conforming bodies do not prove real-service business behavior.
The temporary owned volume was removed and absence verified. The original JSON
and failed runs remain private, outside release packages.

The comparison reported twenty-eight model HTTP responses: twenty-three 200s
and five 429s. Summed reported input/output usage was 514,953/48,449 tokens.
Question waits are not successes. Incremental planning never reached the
algorithm being compared, so this does not establish either mode's superiority.
Some questions concern genuinely undecided policy; others appear to expand scope
or expose native planning limitations. Their semantic classification remains open.

## Verification state

Before versioning, strict typecheck/build, Lint and formatting passed. The enabled
suite passed 1,808 of 1,809 tests, retaining only the previously disclosed Ajv
regression, with zero skips/cancellations. Four original OAS documents passed
59 checks. The host passed 120 files/655 tests, strict types, Lint, formatting,
build and 16 API routes on public 0.4.3 plus its local host changes. These results
are not public 0.4.4 installation evidence.

The versioned 0.4.4 source passed strict typecheck/build, Lint and formatting.
The full enabled suite passed 1,808 of 1,809 in 146.959 seconds, with only the
exact retained Ajv regression and no skips, cancellations or todo cases. Graph
and release checks passed eleven tests; four original OAS files passed 59.
Two isolated n8n suites covered eleven executions: five successes and six
intentional invalid/missing-input stops, with seventeen local HTTP requests.
Temporary validation volumes were removed. These are controlled contract checks,
not additional actual-model scenario completions.

An independent temporary consumer installed all three final archives without
workspace symlinks or skipped library checks, passed strict compilation and
executed the original 34-operation OAS smoke. It made no model or business-service
calls. Package/export/notices/private-artifact checks and SHA-512 checks passed;
the independently installed archives must match the final source rebuild before
publication. No local archives are installed into Qoopilot.

Remote source/tag, public downloads, GitHub publication and local host installation
will be recorded separately after they actually finish. Source synchronization
must precede publication; npm alone is not completion.

## Known limitations

Ajv 8.20.0 still rejects the retained `properties.__proto__` regression; the owner
authorized disclosure rather than an OAS/data rewrite. The fresh production
dependency audit reports High 5 and all other severities zero, unchanged from
0.4.3, on the upstream n8n SDK/Zod dependency chain. External dependency versions
are unchanged. No all-tests-pass or clean-audit assertion is made.

Full five-scenario completion, the necessity of each model question, unsupported
native planning behavior, incremental connection quality and UI behavior after
public 0.4.4 installation remain unverified. This release is not completion of
the larger user-outcome goal.
