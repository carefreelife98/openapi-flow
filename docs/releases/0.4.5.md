# 0.4.5 release

Published and locally adopted on 2026-10-28. Exact source commit
`2fa3f691ea97cd17a3fffd50ae510e23a9b912d9` was pushed to `origin/main` before
publication; annotated `v0.4.5` points to the same commit. All three public npm
version records and downloaded archives match the verified SHA-512 values.
The [GitHub Release](https://github.com/carefreelife98/openapi-flow/releases/tag/v0.4.5)
is published, not draft/prerelease, and its notes and tag commit were verified.
The product installs exact public 0.4.5, with other lock entries unchanged.
Company push, Cloud and existing user-server restart were not performed.

## Publication and local installation

Public npm verification initially observed 404 after the successful publish
commands; subsequent exact version records returned 200 and downloaded archives
matched. No existing version was republished and no tag was moved.

The public archives contain 1,152 Core, 444 LangChain and 434 n8n files; every
installed file matched its public archive. The local product passed `yarn verify`
in 155.73 seconds: 120 files/655 tests, format, Lint, strict typecheck, production
build and 16 generated API routes. It imports the new feature enum and adds Korean
presentation text without redefining its types or behavior. This installation
check is not a new whole-scenario generation or browser quality result.

## Post-release whole-scenario check and unpublished follow-up

A fresh original-scenario run with public 0.4.5 selected ten API calls and six
native roles, then failed during native parameter reference validation after
299.920 seconds. No import JSON, connection comparison or new UI success was
produced. This does not change the published release artifacts or tag.

The gather runtime emits selected sources in order, but its released output
schema describes an unordered set. A controlled planning-model replay requested
that missing positional guarantee. The uncommitted follow-up declares each
position using `prefixItems`, preserving all original bodies and provenance.
With that candidate, planning-model settings completed three isolated engine
conditions with ten reads each and expected outcomes. The connections were fixed
verification materials, not a new full generation. A detail-model proposal passed
technical checks but misrepresented the empty-list policy; host native semantic
configuration is being assigned to the planning model instead.

Candidate checks passed fourteen focused cases, fifty-nine original-OAS cases,
five isolated gather conditions and strict type/build, Lint and format checks.
The enabled suite passed 1,815/1,816 with only the retained Ajv failure. The
positional contract is not part of published 0.4.5; another authorized patch and
a fresh original input-to-JSON/engine/UI run are still required. Product source,
Cloud and existing user servers have not been published or restarted.

## Scope

- Add reusable response-evaluation data, rather than extending assertion failure
  handling or inserting service-specific classification in the host.
- Reuse existing strict comparison, source validation, material binding and SDK
  assembly. Add resource-aware dynamic object-value projection in Core.
- Expose parameters, results, policies and schemas through public package APIs.
- Keep business policies in scenario input, and technical contract errors in the
  error path. Preserve original values, item ancestry and comparison provenance.

## Known limitations and pending release work

Version-aligned release checks completed on 2026-10-28: strict typecheck/build,
Lint, format, actual graph/release checks, the enabled 1,815-test suite (1,814
passed and only the exact previously accepted Ajv failure), 59 original-OAS
checks, five isolated evaluation conditions and the independent packaged
consumer. All three intended 0.4.5 archives passed package-content/export checks
and SHA-512 verification before publication.

The fresh npm audit returned the same five High dependency entries as the
previous release, with no Moderate/Critical entries. These are the existing
n8n dependency chain warnings; no third-party package version or override was
changed. The release retains the disclosed limitation rather than claiming a
clean audit or changing dependency contracts to suppress it.

- Existing Ajv special-key and upstream dependency warnings remain; no new clean
  audit is claimed. No dependency version was changed by this implementation.
- Pagination, multi-item request grouping and broad original-five planning quality
  remain independent unfinished work. Do not reinterpret them as implemented by
  a reporting capability.
- A new whole-generation path and UI evaluation using this addition remain
  separate unfinished checks. Exhaustive feature presentation maps must handle
  the new enum; the local product map does so.
- This record follows publication; the version tag remains on the exact release
  source above. Local adoption remains distinct from company push, Cloud and
  restarting existing user servers.
