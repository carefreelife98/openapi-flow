# 0.5.1 release record

The owner requested local Qoopilot adoption and actual-model/isolated-engine
verification on 2026-10-29. Adoption requires a public registry release under the
host's package provenance rules. The source-first release includes the reviewed
binding-candidate, precedence, bounded-rejection APIs and the preceding OAS
server-resolution/goal-review fixes. Company source, private specifications,
credentials and local evaluation artifacts are excluded.

## Preparation

Versions and internal dependencies are aligned at 0.5.1. Third-party lock records
are unchanged. Existing model fixture assertions retain their original expected
bindings while encoding the new candidate output format.

Earlier focused checks passed 43 binding tests, 16 original-OAS contract tests,
5 graph-document tests and 33 host regressions. An isolated incremental n8n run
completed two executions with ten local requests. Actual Chomsky transport
accepted the strict schema; the original private-spec semantic-selection
mismatch is preserved. These observations predate the final release verification
and do not establish host adoption or whole-workflow quality.

Final verification, exact source/tag provenance, public archive integrity,
published GitHub Release and host adoption are recorded separately below when
completed. Publication and company deployment are distinct actions. No company
push, Cloud deployment or existing user-server restart is included.

## Publication and local adoption

Release source `d4e696b306e7b35640a91106a4a9e05eb5a4af0b` was pushed to
`origin/main` before publication. The remote peeled annotated `v0.5.1` tag
matches that exact commit. All three public npm version records and downloaded
SHA-512 archives match the independently tested release files. Early registry
lookups returned 404 during processing; no package was republished.

[GitHub Release v0.5.1](https://github.com/carefreelife98/openapi-flow/releases/tag/v0.5.1)
is published, with its tag, non-draft state and notes verified. The local host's
API and shared contract workspaces use the public 0.5.1 packages. All 2,088
installed package files match the public archives without workspace links.
Only the three OSS package blocks changed in the host lockfile; third-party
blocks are unchanged. Install scripts were disabled.

The host composes candidate planning with per-call checkpoints and a bounded
rejection-repair policy. Its final full verification passed 126 files and 682
tests, static checks, build and 16 generated routes. Older fixtures still
expected deployment overrides, free-pointer model output and the former
single-pass default; fixtures were updated to the current contracts while
preserving their expected requests, bindings and rejection assertions.

Five fresh incremental natural-language examples using the actual host and
provider produced one final JSON, three native-stage planning stops and one
unresolved API-choice review. The generated example's canonical draft was
compiled with isolated addresses and synthetic credentials, preserving its
values and business connections. Two executions with twelve local requests
preserved the original string, array and empty-array responses. This is one
observed generated example, not a general success-rate estimate.

A separate real-spec/provider binding check used the product's bounded planner
and code-derived two-API dependency graph. Two isolated executions with four
requests passed distinct response values to the next request rather than
reusing the initial literal. That scoped check is not counted as another full
natural-language workflow-generation success. The earlier semantic mismatch
remains in the historical evidence.

The private evaluation tool retained an obsolete ten-run assertion and an old
terminal-output accessor. Original model/engine outputs and tool failures were
preserved; postflight checks and offline reassessment corrected the tool without
rerunning the model to improve the score. Runtime output hashes stayed unchanged
throughout generation. Business API calls, company push, Cloud deployment and
existing user-server restarts were not performed.
