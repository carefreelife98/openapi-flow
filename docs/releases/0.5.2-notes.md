# openapi-flow 0.5.2

IF planning now supports unary `exists`, `notExists`, `isEmpty` and
`isNotEmpty` predicates over declared API/native output pointers. Missing
optional parents are evaluated without substituting data. Existing binary
comparisons, source validation and type checks remain strict. Generated flows
use the official n8n IF node. Use an existence gate before strict comparisons
that require a value.

The new `N8nNativeFeature.EmitLiteralData` (`emit-literal-data`) creates typed
scalar result fields with the official n8n Edit Fields node. It can record a
branch outcome or skip explanation without requiring a host-defined input
schema. It does not fabricate API responses or replace required API inputs.
The feature inventory gains one member; hosts with exhaustive presentation
maps must add its UI entry. Existing custom `json-output` contracts remain
unchanged.

This release also includes the already-merged planning contract fixes since
0.5.1: preserved source messages for requested enum selection, explicit binding
key choices and provenance, schema resource handling, and read-only workflow
context for native repair. Existing source permissions remain separate from
that context; it does not authorize new connections or arbitrary value changes.

## Verification and limitations

The implementation passed build/typecheck, lint and formatting checks. The
pre-version regression run passed 1,893 of 1,894 tests; the remaining failure is
the previously documented Ajv handling of the literal `__proto__` property.
Final focused regressions passed 39/39. They exercise generated IF guards and
expressions, typed literal output, planning inventories and reference contracts.

The new feature has not yet been verified with a live model or the n8n execution
engine. Docker was unavailable during this verification. These results do not
establish end-to-end generation quality or business-service execution success.
Our source is MIT; dependency license conditions, including n8n's, still apply.
