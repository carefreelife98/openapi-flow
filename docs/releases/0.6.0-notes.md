# openapi-flow 0.6.0

Tracked API argument generation now selects original sources instead of asking
the model to produce both values and their evidence. Core copies each selected
JSON value with its original type and validates the assembled request against
the OpenAPI literal contract. Original text selections are verified once and
copied as strings. There is no implicit type conversion or source replacement.

Model-visible source choices and output schemas now share input-root-specific
candidate lists. A numeric JSON token cannot be selected for a string input
root. Primitive roots do not expose nonexistent descendant inputs. Original
messages, confirmed inputs, bindings, and host-owned retry policy keep their
existing ownership.

The source scanner also recognizes numeric literals after explicit assignment
boundaries such as `sequence=0`. Signs, fractions, exponents, malformed numeric
runs, and quoted-string protection remain intact.

## Compatibility

This minor version changes the tracked model wire contract. Custom providers,
mocks, and recorded responses must remove `literalInputs.values`. Select JSON
candidate IDs from the new input-scoped `literalSourceChoices` context. Text
selections supply their exact `sourceText` once. The former duplicated wire is
rejected rather than accepted through a compatibility fallback.

The returned `ApiCallArguments.values` and verified source receipts remain
available. Existing untracked generation is a separate API mode; it is not used
to recover an invalid tracked result. The new public Core function
`resolveApiLiteralValues` provides source-owned value assembly. See
[source-owned API literals](../source-owned-api-literals.md).

## Verification and known limitations

Implementation verification passed 86 focused regressions, build/typecheck,
lint, formatting, and five compiled conversation-graph document checks. The
full implementation suite passed 1,897 of 1,898 tests. The remaining failure is
the previously documented Ajv handling of the literal `__proto__` property; it
has not been skipped or represented as passing.

The version-aligned release check reproduced the same unit result and passed
54 original-OAS regressions. All three package archives passed file-content,
export, version, peer/dependency and SHA-512 checks. An independently installed
consumer passed strict typechecking and runtime compilation without workspace
symlinks or skipped library type checks.

A private consumer used a real model to generate arguments for six original
API call roles. All six matched the supplied inputs and had no unresolved
inputs. These are argument-stage results, not a completed consumer workflow,
n8n engine execution, semantic accuracy benchmark, or service deployment.
Docker was unavailable for a new isolated n8n engine run. Private specifications,
records, model credentials, and business responses are excluded from this
repository and its packages. Dependency licensing, including n8n's conditions,
still applies independently of this repository's MIT license.

The current dependency audit reports 6 high and 11 moderate findings (17 total,
0 critical). External dependency versions were not changed by this release.
These findings remain unresolved; this release does not claim a clean audit.
