# @openapi-flow/n8n

Deterministic OpenAPI request-node creation and explicit n8n DAG assembly with the official workflow SDK. Unreleased `0.2.0` source; this package is not yet published.

- `createHttpRequestNode`: full selected OAS contract + literal values/response bindings + optional trusted base URL/credential references → SDK node fragment. Bound requests additionally require `apiNodeNames` and compile into materialization Code → HTTP Request.
- `httpRequestDeploymentOptionsSchema`: shared validation for optional execution settings. Missing URLs become `https://replace_me.invalid`; required missing Bearer references become `REPLACE_ME:<documentId>:<schemeName>`. Supplied invalid settings fail rather than becoming placeholders.
- `assembleN8nWorkflow`: explicit fragments, named ports, edges and starts → SDK-validated importable JSON. Fan-out is supported; node-array order does not define execution order.
- `createN8nNativeCapabilities`: described Zod configuration schemas and deterministic compilers for IF, Merge Append, response-assertion Code and StopAndError. Custom capability registration is supported.
- `compilePlannedN8nWorkflow`: validates model/host graph plans against materials/capabilities, checks response availability and joins, and builds importable JSON using the SDK.
- `createN8nWorkflowPreview`: catalog + selected APIs + explicitly reported gaps → `{ status: 'needs-review', executable: false, diagnostics, previewWorkflow }`. Uses official SDK `sticky()`/`workflow()` to create an inactive review canvas, not request nodes. No LLM, trigger or execution connections.
- `compileInboundWorkflow`: preserved Webhook/Callback response compilation.

No LLM dependency, HTTP server, workflow import/publication or API execution. Compilation does not require per-path `effectPolicy`; the host owns execution approval. Bound requests read a single unambiguous API full-response envelope, preserve actual JSON types, validate the complete request against its OAS schema and reuse literal serialization. The validator is compiled on the host with [Ajv standalone code generation](https://ajv.js.org/standalone.html); n8n receives no schema compiler or eval requirement. Native comparisons currently read the first output item. Missing required API values fail without defaults. Code is library-owned, not model-written. Multi-node fragments require explicit internal edges, validated and wired by the assembler. Other native variants, item-wise bindings, native-output bindings, transformations and exhaustive response-schema proof remain pending. Earlier policy-aware single/sequence compilers live under `/legacy`.

Template nodes visibly list missing execution settings in their notes. No OAS server is selected automatically, no credential secret is embedded, and anonymous APIs receive no credential placeholder. Provide settings and regenerate before execution, or replace placeholders and select existing n8n credentials. Bound URLs also live in the Materialize node configuration; editing only the HTTP Request URL is insufficient. Fully configured output and strict `/legacy` contracts remain unchanged.

Review previews are different from deployment templates: they contain **only Sticky Notes**, marked `[REVIEW ONLY]`, with `active: false`. API cards identify confirmed OAS contracts, not approved or completed calls. Missing-operation reports have no fabricated method/path; insufficient-contract reports require a valid operation key. Binding/graph issues retain their stage. Optional proposed native node identities/edges are rendered as unvalidated text, never executable nodes or connections. A report does not prove an API is absent. Empty reports, invalid OAS catalogs and stale/missing operation keys fail. This function accepts no request values or deployment/credential settings, but scenario, purpose and report text are included and may contain private data: redact before sharing. Existing compilers continue rejecting gap plans.

Input/output types are in `src/types/workflow-preview.ts`, metadata schemas in `src/schemas/workflow-preview-schema.ts`, and catalog checks, note rendering, Markdown escaping and SDK assembly are separate files in `src/workflow/preview/`. SDK structural validation allows a missing trigger intentionally for this notes-only output. [n8n documents Sticky Notes as workflow annotations](https://docs.n8n.io/build/understand-workflows/workflow-components/add-notes-and-documentation); they are not a substitute for executable validation guards. The isolated test `integration/workflow-preview-local-n8n.mjs` imports/exports three public fixture previews with Docker networking disabled, verifying inactive state, notes, colors, positions and empty connections without executing them.
